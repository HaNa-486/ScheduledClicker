ScheduledClicker frequently asked questions

Platform compatibility, download files, macOS permissions, safety, checksums, timing, and the Codex workflow.

What is ScheduledClicker?

A free, open-source Windows 11 and macOS 13+ scheduling utility. Stable v1.1.2 handles one timed click; preview 1.2.0-preview.1 adds bounded prompt input/send loops, five interface languages and manual light/dark switching.

Does the Windows EXE run on a MacBook?

No. Use the separate universal macOS ZIP, which supports Apple silicon and Intel Macs.

Why does macOS require Accessibility permission?

macOS blocks pointer control until the user explicitly grants permission. ScheduledClicker checks this before arming and cannot click without approval.

Does the macOS app support Dark Mode?

Yes. Version 1.1.1 fixed the initial Dark appearance defect. Light and Dark UI renders and contrast checks run in CI.

Why did only one millisecond digit appear to move?

Version 1.1.1 refreshed its three-digit clock every 100 milliseconds, so the hundreds digit was the most visibly active. Version 1.1.2 refreshes around 30 times per second while keeping scheduling separate.

What is the `.sha256` file?

A small text checksum containing the official fingerprint of the macOS ZIP. Compare it with `shasum -a 256`; it is not an installer.

Can it continue a Codex session after usage resets?

It can click an already-visible Send or Continue button after the reset time displayed by Codex. It does not detect, bypass, reset, or increase any limit.

Is ScheduledClicker safe?

It has no network, telemetry, account, persistence, or third-party package features. Source and verification evidence are public. Fixed-coordinate automation can still misclick if content moves.

Why can Windows SmartScreen warn?

The free EXE is not signed with a commercial certificate. Verify the SHA-256 or build from source.

Why can macOS warn on first launch?

The app is ad-hoc signed but not Apple Developer ID signed or notarized. Control-click → Open and approve it in Privacy & Security.

Does a failed historical GitHub Actions run make the release unsafe?

No. A failed candidate run remains in project history. Releases are made only after later candidate and main runs pass. The v1.1.1 failure shown in the screenshot was an AppKit compile error in an earlier branch commit and was fixed before release.

Does ScheduledClicker support repeating prompts?

The 1.2.0-preview.1 candidate adds bounded recurring prompt input and send clicks. Released v1.1.2 supports one scheduled click only. Use the preview download instructions for loop mode.

How does the loop interval work?

Choose the first execution time and a wait interval measured from the completion of each round. Use one prompt every round or a prompt sequence. A maximum round count or deadline is required; if both are selected, the first reached stops the loop.

Which interface languages are available in the preview?

Traditional Chinese, English, Japanese, Korean and German. Chinese system locales, including Simplified Chinese, select the Traditional Chinese interface. Japanese, Korean and German select their own language; all other locales select English. You can switch languages in either mode.

Does the preview follow my system light or dark appearance?

Yes. It reads the system appearance when the app starts. The shared sun/moon button changes both modes for the current session; restarting reads the system preference again.

Will the loop detect an AI reply or a usage reset?

No. It performs timed input and clicks at captured positions. It cannot detect AI completion, quota availability, changed chats or successful delivery. Choose the interval yourself and keep the target layout unchanged.

Does loop mode use the clipboard?

Yes. It overwrites the clipboard to paste prompts and does not restore the previous contents. Prompts may remain in clipboard history or the target app. Trial mode sends real input; stopping cannot undo a completed paste or click.
