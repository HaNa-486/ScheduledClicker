ScheduledClicker v1.2.0 · Free and open source

Verification, clipboard and input boundaries

Review what v1.2.0 does, what was tested and what fixed-coordinate automation cannot guarantee.

Local processing and clipboard use

The app has no network access, accounts, telemetry or persistent schedules. Loop mode writes prompt text to the system clipboard and does not restore its previous contents. Text may remain in clipboard history or the target app. Simple mode does not use the clipboard. Mac Copy diagnostics replaces it only when you press the button.

What was verified

The owner accepted Mac build12004 functionality and passed the Windows prompt-language, custom-text preservation and loop trial checks. Both platform builds run automated scheduling, localization and UI tests. Mac capture/focus identity policies cover same-process sibling windows, top-level changes, unavailable AX and invalid geometry. Native acceptance does not establish every third-party app, display combination or negative path.

Versioned build, test and checksum report · Security notes

Stopping and failure

Cancel and F8 stop future steps. Pause between rounds can resume; pausing mid-round stops. Completed input cannot be undone. Review the target draft before restarting after failure. A completed Send click does not prove delivery, and window identity does not identify the intended chat.

Verify downloads

Use the matching checksum from the download page. A checksum confirms file integrity, not trusted authorship.

Get-FileHash .\ScheduledClicker.exe -Algorithm SHA256
shasum -a 256 ScheduledClicker-macOS-universal.zip

Known limitations

  • Windows is unsigned; macOS is ad-hoc signed and not notarized.
  • Keep the desktop awake, unlocked and the target layout unchanged.
  • Mac loops require regular accessible app windows; Windows elevated apps may reject input.
  • No AI-completion, quota-reset or message-delivery recognition.
  • Clipboard contents and already-pasted drafts can remain after stopping or closing.
