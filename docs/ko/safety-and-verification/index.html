다운로드 검증, 권한 및 사용 제한

ScheduledClicker v1.2.0으로 다른 앱을 조작하기 전에 클립보드 사용, 중지 동작, 검증 범위 및 서명되지 않은 파일의 특성을 확인하세요.

다운로드 및 설치

로컬 동작과 클립보드

앱에는 네트워크 접근, 계정, 광고, 원격 측정이 없습니다. 반복 모드는 클립보드를 덮어쓰며 이전 내용을 복원하지 않습니다. 텍스트가 클립보드 기록이나 대상 초안에 남을 수 있습니다. 간단 모드는 클립보드를 사용하지 않습니다. Mac의 진단 복사도 버튼을 누를 때 클립보드를 덮어씁니다. 예약과 위치는 재시작 후 보존되지 않습니다.

대상 창을 보이는 상태로 유지

컴퓨터를 절전 또는 잠금 상태로 두지 말고 대상 창, 입력란과 대화를 그대로 유지하세요. 고정 좌표는 다른 대화나 이동한 입력란을 구별하지 못합니다. 전송 클릭은 전달 완료를 보장하지 않습니다. AI 답변 확인, 사용량 제한 우회, 초기화 시각 감지는 하지 않습니다.

일시 정지, 취소 및 긴급 중지

회차 사이에 일시 정지하면 재개할 때 남은 대기 시간을 유지하지만 종료 시각은 계속 적용됩니다. 회차 실행 중 일시 정지하면 그 회차를 중단합니다. 취소, F8(일부 Mac 키보드는 Fn+F8) 또는 앱 종료는 이후 동작을 멈추지만 붙여넣은 글이나 완료한 클릭을 취소하지 못합니다. 다시 시작하기 전에 초안을 확인하세요.

무엇을 검증했나요?

소유자가 Mac build12004 기능과 Windows 초기 프롬프트 언어 전환, 편집한 내용 보존, 반복 시험 실행을 확인했습니다. 두 플랫폼의 자동 빌드, 예약, 번역 및 UI 검사를 통과했습니다. 모든 외부 앱, 화면 구성, 권한 거부 상황 또는 실제 긴급 중지 키 동작을 각각 검증했다는 뜻은 아닙니다.

진단 복사는 프롬프트나 창 제목을 수집하지 않지만 OS, 대상 앱과 프로세스/창 식별자를 포함합니다. 공유 전에 확인하세요. 복사하면 클립보드가 덮어써집니다.

빌드 및 검증 보고서 (영어/번체 중국어)

시스템에서 경고가 뜨는 이유는?

Windows EXE는 서명되지 않았습니다. Mac 앱은 ad-hoc 서명이며 Developer ID 서명이나 Apple 공증은 없습니다. 알 수 없는 게시자 경고는 악성 코드, 파일 손상, 조직 정책 차단과 다릅니다. 해당 상황의 안내를 따르며 앱을 실행하려고 시스템 보호를 끄지 마세요.

다운로드 파일 검증 방법

체크섬은 파일이 게시된 내용과 일치하는지 확인하며 제작자의 신뢰성을 독립적으로 증명하지는 않습니다. 해당 .sha256을 텍스트로 열고 64자리 해시를 명령 결과와 비교하세요. 대소문자는 무시해도 됩니다. 다르면 실행하지 말고 공식 링크에서 다시 받으세요. 계속 다르면 신고하세요.

Windows · PowerShell

Windows: PowerShell을 열고 예시 경로를 실제 EXE 경로로 바꾸세요(파일 탐색기에서 우클릭 → 경로로 복사). 아래 명령의 Hash 항목과 ScheduledClicker-Windows.sha256을 비교합니다. 전체 경로를 쓰므로 PowerShell의 현재 폴더는 상관없습니다.

아래는 예시입니다. 다운로드한 파일의 실제 경로로 바꾸세요.

Get-FileHash -LiteralPath "C:\Users\YOUR_NAME\Downloads\ScheduledClicker.exe" -Algorithm SHA256

SHA-256 체크섬 (텍스트 파일)

macOS · Terminal

Mac: 터미널에 shasum -a 256과 공백 하나를 입력한 후 Finder의 원본 ZIP을 터미널로 드래그해 전체 경로를 넣고 Return을 누르세요. 결과의 처음 64자리를 ScheduledClicker-macOS-universal.sha256과 비교합니다. 경로를 직접 입력하면 공백이 있는 경로는 따옴표로 감싸세요.

아래는 예시입니다. 다운로드한 파일의 실제 경로로 바꾸세요.

shasum -a 256 "/Users/YOUR_NAME/Downloads/ScheduledClicker-macOS-universal.zip"

SHA-256 체크섬 (텍스트 파일)

실행이나 사용 중 문제가 있나요?

GitHub Issues로 신고하세요(게시하려면 GitHub 계정 필요). OS 및 앱 버전/빌드, 대상 앱, 재현 단계, 전체 오류를 포함하세요. Mac의 진단 복사는 빌드와 실행 단계 정보를 제공합니다. 공개 전에 확인하고 프롬프트, 개인 대화 또는 개인 파일 경로를 포함하지 마세요. 계정이 없어도 FAQ와 기존 Issues는 읽을 수 있습니다.
